# دليل التثبيت والرفع على GitHub — تطبيق Memory Flow

**ما هذا الملف:** دليل عملي يشرح خطوة بخطوة كيف تثبّت تطبيق Memory Flow على هاتف أندرويد، وكيف ترفع شيفرته إلى GitHub ليُبنى لك ملف تثبيت جديد تلقائيًا.
**لمن هذا الدليل:** لمن لا يعرف البرمجة إطلاقًا. لا يفترض الدليل أي خبرة سابقة، ولا يستخدم أي أوامر نصية.
**ما تحتاجه قبل البدء:** هاتف أندرويد، اتصال بالإنترنت، بريد إلكتروني، وملفان جاهزان: `MemoryFlow-1.2-debug.apk` و`memory-flow-android.zip`.
**الإصدار والتاريخ:** 1.2 — 21 نوفمبر 2026

**ملاحظتان قبل البدء**

- أسماء الأزرار في GitHub مكتوبة هنا بالإنجليزية كما تظهر على الشاشة، ومميّزة بالخط العريض مثل **Upload files**.
- أسماء الأزرار داخل التطبيق عربية، وقد تختلف كلمة أو كلمتان بين إصدار وآخر. ابحث عن المعنى نفسه لا عن الحرف نفسه.

## 1. ما هو التطبيق، وأول ثلاث خطوات بعد التثبيت

**Memory Flow** تطبيق أندرويد للمراجعة بالبطاقات: تجمع مادتك في مجموعات دراسة، تضيف داخل كل مجموعة بطاقات، ثم تراجعها في وضع الدراسة، فتصلك البطاقات على شكل إشعارات على هاتفك.

واجهة التطبيق عربية افتراضيًا وتُقرأ من اليمين إلى اليسار، وتدعم أيضًا الألمانية والإنجليزية.

**الملفات التي بين يديك**

- `MemoryFlow-1.2-debug.apk` — ملف التثبيت. هذا ما تنسخه إلى الهاتف وتضغط عليه ليتثبّت التطبيق. يُقدَّم لك على رابط تنزيل منفصل.
- `memory-flow-android.zip` — الشيفرة المصدرية كاملة، مضغوطة في ملف واحد. هذا هو الملف الذي ترفعه إلى GitHub.
- هذا الدليل — للقراءة فقط، ويوجد داخل مجلد `docs` في الشيفرة المصدريّة.

**أول ثلاث خطوات بعد التثبيت**

1. **اسمح بالإشعارات.** بدون هذا الإذن لا يستطيع التطبيق إيصال البطاقات إليك، فيبدو كأنه لا يعمل.
2. **أنشئ مجموعة دراسة.** المجموعة هي الوعاء الذي توضع فيه بطاقات موضوع واحد.
3. **افتح وضع الدراسة.** هذا هو الوضع الذي يرسل البطاقات إليك للمراجعة.

الخطوات الثلاث مشروحة بالتفصيل في القسم 3.

## 2. كيف تثبّت ملف APK على هاتفك

**ما هو APK؟** ملف تثبيت تطبيق أندرويد، يشبه ملف `.exe` في ويندوز: تضغط عليه فيُثبَّت التطبيق. لا تحتاج متجر تطبيقات.

**قبل البدء:** تأكد أن التنزيل اكتمل. الملف الناقص هو السبب الأول لرسالة «لم يتم تثبيت التطبيق».

### الطريقة الأولى: التنزيل على الهاتف مباشرة

1. افتح رابط تنزيل `MemoryFlow-1.2-debug.apk` في متصفح الهاتف.
2. اضغط زر التنزيل وانتظر انتهاءه.
3. افتح شريط الإشعارات واضغط على الملف، أو افتح تطبيق **الملفات** ثم مجلد **Downloads**.
4. اضغط الملف → **تثبيت** / **Install**.
5. إن ظهرت رسالة تمنع التثبيت، نفّذ خطوات «السماح بتثبيت التطبيقات من مصدر غير معروف» أدناه، ثم ارجع وأعد المحاولة.

**النتيجة المتوقعة:** تظهر أيقونة Memory Flow بين تطبيقات هاتفك، ويظهر زر **فتح** / **Open** عند انتهاء التثبيت.

### الطريقة الثانية: التنزيل على الحاسوب ثم النقل بكابل USB

1. نزّل الملف على الحاسوب.
2. وصّل الهاتف بالحاسوب بكابل USB.
3. على الهاتف، اسحب شريط الإشعارات واختر **نقل الملفات** / **File transfer** (لا تختر «شحن فقط»).
4. على الحاسوب سيظهر الهاتف كنافذة أو قرص. انسخ الملف إلى مجلد **Download** داخله.
5. افصل الكابل، ثم على الهاتف: **الملفات** → **Downloads** → اضغط الملف → **تثبيت**.

**النتيجة المتوقعة:** نفس نتيجة الطريقة الأولى: أيقونة التطبيق على الشاشة.

### السماح بتثبيت التطبيقات من مصدر غير معروف

«مصدر غير معروف» تعني أي تطبيق لم يأتِ من متجر Google Play، مثل المتصفح أو مدير الملفات. يمنع أندرويد التثبيت منها افتراضيًا لحمايتك، فتفعّله مرة واحدة:

1. افتح **الإعدادات**.
2. **التطبيقات** (قد تكون **التطبيقات والإشعارات**).
3. **وصول خاص** / **Special access**.
4. **تثبيت تطبيقات غير معروفة** / **Install unknown apps**.
5. اختر التطبيق الذي تفتح منه الملف: **Chrome** أو **الملفات**.
6. فعّل **السماح من هذا المصدر** / **Allow from this source**.
7. ارجع إلى الملف واضغطه → **تثبيت**.

**النتيجة المتوقعة:** تبدأ شاشة التثبيت بدل رسالة المنع.

**ملاحظة:** قد يظهر تحذير من Google Play Protect لأن التطبيق ليس من المتجر. اختر **تثبيت على أي حال** / **Install anyway**.

## 3. الإعداد الأول على الهاتف

نفّذ الخطوات بهذا الترتيب؛ كل خطوة تعتمد على التي قبلها.

### 3.1 السماح بالإشعارات

1. عند أول فتح سيطلب التطبيق الإذن. اضغط **السماح** / **Allow**.
2. إن كنت قد رفضت سابقًا: **الإعدادات** → **التطبيقات** → **Memory Flow** → **الإشعارات** → فعّل **السماح بالإشعارات**.
3. تأكد أن وضع **عدم الإزعاج** مطفأ.

**النتيجة المتوقعة:** يظهر اسم التطبيق في قائمة الإشعارات، وتصلك إشعاراته بعد إنشاء مجموعة في 3.3.

### 3.2 إيقاف تحسين البطارية

يحاول أندرويد إغلاق التطبيقات العاملة في الخلفية لتوفير الطاقة، فيتوقف وصول البطاقات. استثنِ التطبيق من ذلك:

- **أندرويد الأصلي (Pixel وغيره):** الإعدادات → التطبيقات → Memory Flow → البطارية → **غير مقيّد** / **Unrestricted**.
- **سامسونج:** الإعدادات → البطارية → حدود استخدام الخلفية → تأكد أن التطبيق ليس في قائمة **التطبيقات النائمة**، ثم الإعدادات → التطبيقات → Memory Flow → البطارية → **غير مقيّد**.
- **شاومي (MIUI / HyperOS):** الإعدادات → التطبيقات → إدارة التطبيقات → Memory Flow → فعّل **التشغيل التلقائي**، ثم **توفير البطارية** → **بلا قيود**.
- **هواوي:** الإعدادات → البطارية → تشغيل التطبيقات → Memory Flow → **إدارة يدوية** مع تفعيل كل الخيارات.
- **أوبو / ريلمي / ون بلس:** الإعدادات → البطارية → إدارة بطارية التطبيقات → Memory Flow → **السماح بالنشاط في الخلفية**.

المسارات تختلف قليلًا بحسب الشركة وإصدار النظام. إن لم تجد المسار، ابحث في الإعدادات عن كلمة «البطارية» ثم عن اسم التطبيق.

**النتيجة المتوقعة:** يظهر اسم التطبيق في قائمة «غير مقيّد» أو «بلا قيود».

### 3.3 إنشاء أول مجموعة دراسة

«مجموعة الدراسة» وعاء يجمع بطاقات موضوع واحد، مثل «إنجليزي — الوحدة الأولى».

1. افتح التطبيق.
2. من الشريط السفلي اضغط **مجموعاتي**.
3. اضغط الزر العائم **مجموعة جديدة** أسفل الشاشة.
4. اكتب الاسم (مثل «الألمانية A2»)؛ الوصف والفئة اختياريان.
5. اضغط **إنشاء**.

**النتيجة المتوقعة:** تظهر المجموعة في القائمة، وعدد بطاقاتها صفر.

### 3.4 إضافة بطاقات

**بطاقة واحدة**

1. اضغط **إضافة معرفة** في الشريط السفلي.
2. اختر المجموعة من الشريط الأفقي أعلى الشاشة.
3. اكتب **السؤال / الوجه الأمامي** و**الجواب / الوجه الخلفي**؛ ويمكنك إضافة تلميحين وشرح وأجوبة بديلة.
4. اضغط **حفظ البطاقة**. تبقى الشاشة جاهزة للبطاقة التالية.

**دفعة واحدة (لصق نص)**

5. في الشاشة نفسها اختر **لصق نص**، والصق سطرًا لكل بطاقة بالشكل `die Herausforderung = التحدي` أو `السؤال = الجواب | تلميح 1 | تلميح 2`.
6. اضغط **استيراد الأسطر**.

**ملف TXT فيه مصطلح في كل سطر**

7. اختر **استيراد** → **استيراد من TXT** → اختر الملف.
8. راجع المعاينة: **الموجود** و**المكررة** و**الجديدة**، وأول خمسة أسطر.
9. اضغط **استيراد N مصطلح**.

- السطر `der Tisch = الطاولة` يصبح بطاقة كاملة بسؤال وجواب.
- السطر `der Tisch` وحده يصبح **مسودة**: يُحفظ المصطلح ويظهر في المجموعة، لكنه لا يظهر في المراجعة حتى تضيف الجواب بزر التعديل (✎).
- الجواب البديل: `laufen = يمشي / يجري` يجعل «يمشي» هو الجواب و«يجري» جوابًا بديلًا مقبولًا.
- سطر `Plural: die Erfahrungen` أو `الجمع:` أو `العربية:` بعد المصطلح يُحفظ في شرح البطاقة، وكذلك `Präteritum:` و`Partizip II:` — دون أي حقول جديدة.
- الملفات الكبيرة (1000 مصطلح وأكثر) تُستورد دفعة واحدة.
- المكرر يُتجاهل تلقائيًا، مع تجاهل المسافات الزائدة وحالة الأحرف.

**ملف CSV أو XLSX**

10. اختر **استيراد** → **CSV / XLSX** → اختر الملف، ثم راجع المعاينة وأكّد.

**النتيجة المتوقعة:** يزداد عدد البطاقات داخل المجموعة بمقدار ما أضفت، وتظهر رسالة تأكيد أسفل الشاشة.

### 3.5 تفعيل المجموعة — القرص الدائري

لكل مجموعة قرص دائري بجانب اسمها يعمل مثل مفتاح جهاز: اضغطه فيتحوّل بسلاسة من OFF إلى ON، ويظهر توهّج حول المجموعة وتُكتب تحته كلمة **مفعّلة**. هذا القرص هو المفتاح الحقيقي: ما دام OFF فلن تصلك أي بطاقة من هذه المجموعة.

1. افتح **مجموعاتي**.
2. اضغط القرص الدائري بجانب المجموعة التي تريدها.
3. تأكد أن الحالة صارت **مفعّلة** (وليس مجرد حركة بصرية).
4. لتفعيل عدة مجموعات: اضغط قرص كل واحدة على حدة، أو استخدم **تفعيل الكل** أعلى القائمة.

**قاعدة مهمة:** الإشعارات لا تخلط أبدًا بطاقات من مجموعة غير مفعّلة، وإيقاف مجموعة لا يمسّ تقدّمها المحفوظ.

### 3.6 تشغيل التعلّم ومراجعة البطاقات

1. افتح **الرئيسية**.
2. القرص الكبير في الأعلى هو **وضع التعلّم**: اضغطه ليصبح مفعّلًا.
3. سيبدأ التطبيق بإرسال سؤال من إحدى المجموعات المفعّلة داخل نافذة الوقت المسموحة.
4. عند وصول الإشعار: اكتب الجواب في حقل الرد داخل الإشعار واضغط **إجابة**، أو اضغط **تلميح 1** لطلب التلميح الأول ثم الثاني. طلب تلميح ثالث يُحتسب إجابة خاطئة. وإن لم تعرف الجواب، اضغط **لا أعرف** ليظهر الجواب وتُسجَّل الكلمة كضعيفة.
5. لعرض البطاقة داخل التطبيق بدل الإشعار، اضغط الإشعار نفسه أو زر **مراجعة الآن**.

**النتيجة المتوقعة:** وصول أول بطاقة في شكل إشعار. إن لم تصل، راجع 3.1 و3.2 والقسم 8.

### 3.7 نسخ بياناتك احتياطيًا أو تصديرها

1. افتح **الإعدادات** → قسم **البيانات**.
2. **تصدير CSV** أو **تصدير XLSX**: يحفظ بطاقاتك في ملف تفتحه Excel.
3. **نسخة احتياطية كاملة**: ملف JSON يحفظ المجموعات والبطاقات وتقدّمها.
4. **استعادة نسخة**: يعيد بيانات النسخة الاحتياطية في مجموعات جديدة، ولا يمسّ المجموعات الموجودة.

**النتيجة المتوقعة:** رسالة تأكيد بعدد البطاقات المصدرة أو المستعادة.

### 3.8 الكلمات التي لا أعرفها (Weak Words)

1. أثناء الاختبار اضغط **لا أعرف** — أو أخطئ في الجواب.
2. تظهر الإجابة الصحيحة، وتُسجَّل الكلمة في قائمة **الكلمات التي لا أعرفها**.
3. في **الرئيسية** تجد بطاقة **الكلمات التي لا أعرفها** وعددها، وزر **ابدأ الاختبار** لمراجعتها وحدها.
4. الكلمات الضعيفة تظهر أولًا في المراجعة العادية وفي الإشعارات.
5. كل إجابة صحيحة تُنقص عدّاد الضعف، وبعد إجابات صحيحة بعدد أخطائك تخرج الكلمة من القائمة.

**أنواع الأسئلة** تتنوّع تلقائيًا: من الألمانية إلى العربية، من العربية إلى الألمانية، واختيار من أربعة.

**جلسة اليوم** محدودة بعدد **بطاقات جديدة يوميًا** في الإعدادات (10 افتراضيًا)، فلا تظهر 500 كلمة مرة واحدة.

## 4. كيف تنشئ حساب GitHub

GitHub موقع لحفظ الشيفرة البرمجية وبنائها. الحساب مجاني ولا يحتاج بطاقة دفع.

1. افتح `github.com` في المتصفح.
2. اضغط **Sign up**.
3. اكتب بريدك الإلكتروني → **Continue**.
4. اكتب كلمة مرور قوية → **Continue**.
5. اكتب اسم مستخدم بالحروف اللاتينية (سيظهر داخل رابط مستودعك لاحقًا) → **Continue**.
6. أجب عن سؤال تفضيلات البريد الإلكتروني بأي اختيار؛ لا يؤثر على شيء.
7. حلّ لغز التحقق الظاهر (تحريك قطعة إلى موضعها) → **Submit**.
8. افتح بريدك؛ ستجد رسالة من GitHub فيها رمز تحقق. اكتب الرمز في الصفحة.
9. عند سؤال الخطة اختر **Free**.

**النتيجة المتوقعة:** تفتح الصفحة الرئيسية لحسابك، وفي أعلى اليمين صورتك الرمزية.

## 5. كيف تنشئ مستودعًا باسم memory-flow-android

«المستودع» (Repository) مجلد مشروعك على GitHub: يحفظ الملفات، ويسجّل كل تعديل يطرأ عليها.

1. سجّل الدخول إلى GitHub.
2. اضغط علامة **+** في أعلى يمين الصفحة → **New repository**.
3. في خانة **Repository name** اكتب بالحروف اللاتينية تمامًا: `memory-flow-android`.
4. خانة **Description** اختيارية، مثل: `Memory Flow Android app`.
5. اختر **Public** إن لم يكن لديك سبب لإخفاء الشيفرة.
6. **أهم خطوة:** لا تُعلّم أي مربع في قسم التهيئة. اترك **Add a README file** و**Add .gitignore** و**Choose a license** فارغة. المستودع يجب أن يبدأ خاليًا حتى تُرفع ملفاتك كما هي دون تعارض.
7. اضغط **Create repository**.

**النتيجة المتوقعة:** صفحة فيها عنوان **Quick setup** ورابط بالشكل `https://github.com/اسم-المستخدم/memory-flow-android`. انسخ الرابط واحفظه في مكان تجده لاحقًا.

## 6. كيف ترفع الشيفرة من صفحة الويب

كل ما في هذا القسم يجري داخل المتصفح؛ لا تحتاج تثبيت أي برنامج.

### 6.1 فك الضغط

1. على ويندوز: انقر على `memory-flow-android.zip` بالزر الأيمن → **Extract All** → **Extract**. على ماك: انقر نقرًا مزدوجًا.
2. افتح المجلد الناتج. يجب أن ترى داخله ملفات المشروع مباشرة، ومنها مجلد اسمه `.github`.
3. إن وجدت مجلدًا وحيدًا يحمل الاسم نفسه ولا شيء غيره، ادخل إليه؛ بعض برامج فك الضغط تضيف طبقة مجلد زائدة.

### 6.2 البدء بالرفع

1. افتح صفحة مستودعك.
2. اضغط **Add file** (قرب أعلى قائمة الملفات) → **Upload files**.
3. ستظهر منطقة كبيرة مكتوب فيها اسحب الملفات وأفلتها.

### 6.3 السحب الصحيح — أهم خطوة في هذا الدليل

1. افتح المجلد الذي فككت الضغط عنه في نافذة أخرى.
2. حدّد **كل ما بداخله**: `Ctrl + A` في ويندوز، `Command + A` على ماك.
3. اسحب التحديد كاملًا وأفلته في منطقة الرفع.

**لا ترفع** ملف الـ zip نفسه، و**لا ترفع** المجلد الخارجي كطبقة إضافية. المطلوب محتوى المجلد، لا المجلد.

4. تأكد أن قائمة الملفات المرفوعة تضم `.github/workflows/android-build.yml`. هذا الملف هو الذي يجعل GitHub يبني التطبيق تلقائيًا؛ إن لم يُرفع فلن يبدأ أي بناء. إن كان مدير الملفات يخفي المجلدات التي تبدأ بنقطة، فعّل **إظهار العناصر المخفية**.
5. انتظر انتهاء شريط الرفع؛ قد يستغرق دقائق بحسب سرعة اتصالك.

### 6.4 الحفظ

1. في صندوق **Commit changes** اكتب وصفًا قصيرًا، مثل `first upload`.
2. اضغط **Commit changes**.

**النتيجة المتوقعة:** تعود إلى قائمة ملفات المستودع، وفيها ملفات مشروعك ومن بينها `.github`.

**إن رفض المتصفح رفع عدد كبير من الملفات في مرة واحدة:** ارفعها على دفعتين، وأنهِ كل دفعة بـ **Commit changes** قبل البدء بالثانية.

## 7. كيف تتابع البناء التلقائي وتنزّل ملف APK

بعد كل حفظ (**Commit**) يبدأ GitHub بناء نسخة APK تلقائيًا، لأن المستودع يحتوي على `.github/workflows/android-build.yml`.

1. في صفحة المستودع اضغط تبويب **Actions**.
2. ستجد سطرًا باسم وصف الحفظ الذي كتبته (`first upload`). أمامه رمز يدل على الحالة: نقطة صفراء = البناء جارٍ، علامة صح خضراء = نجح، علامة خطأ حمراء = فشل.
3. اضغط على السطر لفتح صفحة التشغيل (**Summary**).
4. انزل إلى أسفل الصفحة حتى قسم **Artifacts**.
5. اضغط `memory-flow-debug-apk`. سيُنزَّل ملف مضغوط (zip).
6. فك ضغطه؛ ستجد داخله ملف APK. ثبّته كما في القسم 2.

**النتيجة المتوقعة:** ملف APK جديد يعمل على هاتفك. كل حفظ جديد يُنشئ نسخة جديدة تظهر في **Artifacts** بالطريقة نفسها.

## 8. أسئلة شائعة

**1. لا تصلني الإشعارات.**
راجع إذن الإشعارات (3.1)، ثم استثناء البطارية (3.2). تأكد أن وضع عدم الإزعاج مطفأ، وأنك لم تسحب التطبيق لإغلاقه من قائمة التطبيقات الأخيرة. إن كنت تستخدم مانع إشعارات أو وضع توفير طاقة شديد، استثنِ التطبيق منه.

**2. لا أستطيع الكتابة مباشرة داخل الإشعار.**
بعض الهواتف — خصوصًا على شاشة القفل — تمنع ظهور لوحة المفاتيح داخل الإشعار. اضغط الإشعار ليفتح التطبيق وأجب هناك. جرّب أيضًا فتح قفل الشاشة أولًا ثم الإجابة من الإشعار.

**3. البناء فشل (علامة حمراء في Actions).**
افتح **Actions** → التشغيل الفاشل → اقرأ اسم الخطوة التي توقفت عندها (غالبًا **Build** أو **Run**). أشهر سبب مرتبط بهذا الدليل: مجلد `.github` لم يُرفع أو رُفع ناقصًا. أعد رفع محتوى المجلد كاملًا ثم **Commit changes**، وسيبدأ بناء جديد تلقائيًا.

**4. بعد الرفع لا تظهر كل المجلدات.**
ثلاثة أسباب محتملة: رفعت المجلد الخارجي بدل محتواه فظهرت طبقة إضافية؛ أو لم يكتمل الرفع وأغلقت الصفحة قبل انتهائه؛ أو كان المجلد فارغًا — فGit لا يحفظ المجلدات الفارغة إطلاقًا. تحقق من وجود `.github` في القائمة، وأعد الرفع من داخل المجلد.

**5. نسيت رابط المستودع.**
سجّل الدخول → صورتك في أعلى اليمين → **Your repositories** → اختر `memory-flow-android`. الرابط دائمًا بالشكل `https://github.com/اسم-المستخدم/memory-flow-android`.

**6. الهاتف يقول «لم يتم تثبيت التطبيق».**
تحقق بالترتيب: الملف ناقص (أعد التنزيل وانتظر انتهاءه)؛ المساحة غير كافية؛ تحاول تثبيت نسخة أقدم من نسخة مثبّتة بالفعل؛ أو النسخة الجديدة موقّعة بمفتاح مختلف فلا تُثبَّت فوق القديمة وتحتاج إزالة القديمة أولًا — وهذا يمحو بياناتها، فراجع السؤال 9 قبل أن تفعل.

**7. الإشعارات كثيرة.**
افتح **الإعدادات** داخل التطبيق → **الإشعارات**: قلّل **أقصى عدد إشعارات يوميًا** و**أقصى عدد أسئلة يوميًا**، واختر وتيرة **هادئة**، واضبط **ساعات الهدوء**. ومن إعدادات أندرويد يمكنك أيضًا إسكات فئة الإشعارات كليًا. تقليل عدد المجموعات المفعّلة يقلل العدد كذلك.

**8. كيف أنسخ بياناتي احتياطيًا؟**
افتح **الإعدادات** → **البيانات** → **نسخة احتياطية كاملة**، واختر مكان حفظ ملف JSON. لاستعادته لاحقًا: **استعادة نسخة**. راجع 3.7.

**9. هل أفقد البيانات إذا حذفت التطبيق وأعدت تثبيته؟**
نعم في الغالب: حذف التطبيق من أندرويد يحذف بياناته معه. أما التحديث — أي تثبيت نسخة أحدث بنفس التوقيع وبرقم إصدار أعلى فوق القديمة — فيحفظ بياناتك ولا يمسّها.

**10. هل يعمل دون إنترنت؟**
نعم، بالكامل. التطبيق لا يطلب إذن الإنترنت أصلًا: البطاقات والتلميحات والجدولة والإحصاءات كلها على الهاتف. الذي يحتاج إنترنت هو GitHub فقط: الرفع والبناء وتنزيل الملفات.

**11. هل يعمل على iPhone؟**
لا. `MemoryFlow-1.2-debug.apk` ملف أندرويد فقط، ولا يُثبَّت على iOS.

**12. هل أحتاج حاسوبًا؟**
لا. يمكنك تنزيل APK من متصفح الهاتف، ورفع الملفات من متصفح الهاتف أيضًا. الحاسوب أسهل في فك الضغط وسحب مجلد كامل، لكنه ليس شرطًا.

**13. كيف أحدّث التطبيق إلى نسخة جديدة؟**
ثبّت ملف APK الجديد فوق القديم مباشرة. لا تحذف القديم. تبقى بياناتك كما هي.

**14. هل أرفع كل الملفات في كل تحديث؟**
الأسهل أن ترفع محتوى المجلد كاملًا من جديد. GitHub يستبدل الملفات المتشابهة ويضيف الجديدة، فلا تتكرر الملفات.

**15. كيف أتأكد أن التطبيق يعمل كما يجب؟**
افتح **الإعدادات** → **التشخيص** → **الفحص الذاتي** → **تشغيل الفحص**. يشغّل التطبيق اختبارات حقيقية على قاعدة بيانات مؤقتة (لا تمسّ بياناتك) ويعرض النتيجة: ناجح أو فاشل، وأربعة بنود تتعلّق بالهاتف تُعلَّم «يتطلب جهازًا».

## 9. قاموس المصطلحات

- **APK:** ملف تثبيت تطبيق أندرويد.
- **Repository / مستودع:** مجلد مشروعك على GitHub مع سجل كل تعديلاته.
- **Commit:** عملية حفظ. كل حفظ يسجّل صورة من الملفات في لحظة معينة مع وصف قصير.
- **Actions:** تبويب في GitHub ينفّذ خطوات آلية عند كل تعديل. في هذا المشروع يبني ملف APK.
- **Artifacts:** الملفات الناتجة عن تشغيل **Actions**، ومنها ملف APK الذي تنزّله.
- **Debug / نسخة تصحيح:** نسخة للتجربة، تُبنى أثناء التطوير وتُثبَّت بسهولة خارج المتجر. النسخة التي بين يديك من هذا النوع.
- **Release / نسخة إصدار:** نسخة نهائية موجّهة للنشر العام.
- **Workflow / سير عمل:** ملف يصف خطوات البناء الآلي؛ في هذا المشروع هو `.github/workflows/android-build.yml`.
- **versionCode:** رقم داخلي يزداد مع كل نسخة جديدة، ويقارن به أندرويد بين النسخ ليعرف الأحدث.
